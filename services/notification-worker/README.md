# Notification worker

A Node.js Redis Streams consumer illustrates the asynchronous part of a trace. It extracts the producer's W3C carrier and creates one consumer span per delivery attempt. JSON business logs go to stdout for the Collector's filelog receiver. The Sentry SDK captures only the final exhausted error through an errors-only OpenTelemetry bridge.

The global stream is `workshop:notifications`; consumer group `notification-workers`. Attempts are persisted by message ID in `workshop:attempts`. `success` completes on attempt one, `recover` fails twice and completes on attempt three, and `exhaust` moves to `workshop:dead-letters`. Retries wait 250/500 ms, and pending messages are reclaimed after two seconds. A Redis Lua transaction atomically appends the dead letter, stores its stable event ID, and hands its exception plus trace carrier to `workshop:error-outbox`. The terminal result is stored through fulfillment before acknowledgement. A separate drain retries error delivery, so Sentry availability never determines application status. An atomic Lua script prevents duplicate DLQ entries; deterministic Sentry event IDs deduplicate replayed terminal events.

This workshop runs a single worker replica. Notification delivery is a deterministic provider simulation. A production delivery provider would need an idempotency key. The error outbox can resend the same deterministic event ID after a crash, while a failed flush leaves its exception pending for recovery. The drain requires both a successful SDK flush and a successful transport HTTP response before deleting the outbox entry; indexing is verified separately. Errors retain the original attempt span IDs and original stack. SDK consecutive-event deduplication is disabled so independent workshop runs and outbox replays reach ingestion with their own event IDs. Live verification therefore checks the persisted event in Sentry.

Required runtime settings: `REDIS_URL`, `FULFILLMENT_ADDR`, `SENTRY_DSN`, `SENTRY_RELEASE`, `WORKSHOP_ENVIRONMENT`, and `OTEL_EXPORTER_OTLP_ENDPOINT`. Optional downward-API fields: `POD_UID`, `POD_NAME`, `POD_NAMESPACE`, `NODE_NAME`. Health listens on port 8080 at `/health/live` and `/health/ready`.

Build from the repository root: `docker build -f services/notification-worker/Dockerfile -t workshop/notification-worker:local .`. TypeScript maps are generated with embedded source; the root source-map script injects and uploads the exact image assets without putting an auth token in the image.

The producer’s W3C baggage carries run, session, and scenario. A span processor copies those fields to every span created in the extracted context, and JSON logs fall back to the same baggage when the caller does not supply them. Queue housekeeping before a message is read has no workflow identity yet.
